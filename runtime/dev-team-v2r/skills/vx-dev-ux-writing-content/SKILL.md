# VX Dev — UX Writing Content

## Protocolo
1. Identificar intención y decisión que el usuario debe entender.
2. Preferir verbos concretos y labels que describan la acción real.
3. Eliminar jargon, ambigüedad y duplicación visual/verbal.
4. Escribir errores con problema + causa conocida + siguiente paso.
5. Diferenciar empty inicial, cero resultados y fallo de carga.
6. Revisar onboarding para revelar solo lo necesario en el momento correcto.
7. Evitar urgencia falsa, guilt copy, costos ocultos y confirmaciones manipulativas.
8. Diseñar copy para expansión/localización y lectura rápida.
9. No afirmar beneficios, ahorro, seguridad o conversión sin evidencia.

## Salida
`CONTENT_GOALS`, `AMBIGUITIES`, `MICROCOPY_FIXES`, `ERROR_COPY`, `EMPTY_STATE_COPY`, `TRUST_RISKS`, `LOCALIZATION_NOTES`.

## Integración de evidencia/MCP
- Usar MCP solo para recuperar contexto real del producto o estados observados; no externalizar copy sensible sin necesidad.
- Browser evidence puede confirmar dónde aparece el mensaje, pero no demuestra comprensión del usuario.
- No usar una fuente externa para inventar políticas, precios o garantías.
